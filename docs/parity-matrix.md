# Stable-release parity matrix

Traceability matrix for the NEO feature inventory (parent spec
[#12](https://github.com/soubarnak/leo/issues/12), source inventory:
[void-native-parity.md](research/void-native-parity.md)). Every row records
a fixture (path and sha256), an action, semantic and visible expectations,
automated evidence, a build commit, a Debian version and a status.

Release label: preview
Platform claim: Debian stable amd64 XFCE/X11
Wayland/niri: not claimed
Default Debian version: Debian GNU/Linux 13 (trixie)

Status vocabulary: `pass` (verified by the recorded evidence described
below), `pending-evidence` (automated evidence not yet recorded on Debian),
`pending-manual` (requires a clean-machine or live-service session),
`pending-signoff` (requires the maintainer judgement in
[stable-release-signoff.md](manual/stable-release-signoff.md)). While any
row is not `pass`, the release label must stay `preview`.

## How evidence is recorded

1. `scripts/record_parity_evidence.py --output docs/evidence/<name>.json
   --build-dir build` runs the local suite and records every test result
   with the git commit and host OS.
2. `scripts/debian_release_drill.sh --podman --previous-ref <sha>
   --output-dir build/drill-out` builds and tests the package in a clean
   Debian stable container; the JUnit file and the container's
   `/etc/os-release` are recorded with the same recorder using `--junit`
   and `--os-release`.
3. `scripts/check_parity_matrix.py` (ctest name `leo-parity-matrix`)
   validates this document: column completeness, fixture hashes, evidence
   matches, build-commit tree identity, Debian version agreement and the
   preview-label rule. A row may only read `pass` when a recorded Debian
   run at its build commit passed every cited test or script.

Fixture digests are sha256 of the file, or of a directory's sorted
`sha256  path` listing (recompute with
`python3 -c 'import sys; sys.path.insert(0,"scripts"); from
check_parity_matrix import compute_fixture_hash as h; print(h(".",
"<path>"))'`).
