# Debian packaging and desktop integration contract for LEO

Research date: 2026-09-28. This investigates [Establish the Debian packaging and desktop integration contract](https://github.com/soubarnak/leo/issues/8) for the [LEO Debian rebuild map](https://github.com/soubarnak/leo/issues/1). The supported target is Debian 13 “trixie” on amd64 with XFCE/X11. The maintainer develops on Debian testing (forky/sid). This is a planning contract, not evidence that a native application or package has been built.

The source baseline is NEO 0.7.9 at commit `6dd75296d17644098ff53701d324ba7baf70da49`. The [source inventory and parity baseline](https://github.com/soubarnak/leo/blob/da40475632f36e5f3cca92ffcd986fc6412c96e3/docs/research/void-native-parity.md) describes its desktop features and format risks. The [library compatibility decision](https://github.com/soubarnak/leo/issues/4#issuecomment-5843571906) governs saves, Pocket handoff, recovery, and rollback. The earlier [Void integration research](https://github.com/soubarnak/leo/blob/da40475632f36e5f3cca92ffcd986fc6412c96e3/docs/research/void-native-integration.md) is background only; its XBPS and Wayland assumptions do not apply to this target.

## Recommended contract

For the current Qt 6 Widgets/C++ candidate, plan a Debian binary `.deb` built with CMake and debhelper against **trixie's system libraries**. [Validate native editing and choose the stack](https://github.com/soubarnak/leo/issues/5) still owns the final toolkit choice. APT owns installation, upgrade, and removal. Do not bundle a Qt runtime, Electron, a webview, Flatpak, or AppImage. Put executable and resources in package-owned `/usr` paths; keep the existing `NEO Library` in the user's Documents area, and put private application data in XDG locations outside that library. The product shown to users is **LEO**. Keep library filenames, formats, domain markers, unknown metadata, and Pocket interoperability unchanged. This is an identity rename, not a library migration. [Debian Policy on source builds](https://www.debian.org/doc/debian-policy/ch-source.html), [Debian Policy on desktop entries](https://www.debian.org/doc/debian-policy/ch-opersys.html), [Qt standard paths](https://doc.qt.io/qt-6.8/qstandardpaths.html), [existing library path](../../main.js), [Pocket's shared path](../../pocket/README.md).

Use a collision-free installed command. Debian trixie already ships `/usr/bin/leo` in `libwww-dict-leo-org-perl`; its [trixie file list](https://packages.debian.org/trixie/all/libwww-dict-leo-org-perl/filelist) and [package description](https://packages.debian.org/trixie/libwww-dict-leo-org-perl) both identify that command. [Debian Policy §10.1](https://www.debian.org/doc/debian-policy/ch-files.html#binaries) requires unrelated programs on `PATH` to have different filenames and says renaming is usually preferable to a package conflict. **Recommended provisional names:** Debian package `leo-writer`, command `/usr/bin/leo-writer`, desktop file and app ID `io.github.soubarnak.LeoWriter.desktop` / `io.github.soubarnak.LeoWriter`, icon name `io.github.soubarnak.LeoWriter`, XDG directory suffix `leo-writer`, and visible `Name=LEO`. Recheck name availability before publication. These exact names are a product decision for a follow-up ticket; the non-collision rule is part of this contract. Do not displace the dictionary tool with `Conflicts`/`Replaces` merely to claim `/usr/bin/leo`. [Debian package relationships](https://www.debian.org/doc/debian-policy/ch-relationships.html#conflicting-binary-packages-conflicts), [desktop ID rules](https://specifications.freedesktop.org/desktop-entry/latest-single/), [Qt display and desktop file names](https://doc.qt.io/qt-6.8/qguiapplication.html).

## Stable baseline and dependency assumptions

[Debian Releases](https://www.debian.org/releases/) identifies **13 “trixie” as stable**, initially released 2025-08-09 and at point release **13.7 on 2026-09-12**; **forky** is testing and **sid** is unstable. Pin the target to the `trixie` suite, not the moving `stable` alias, when building and validating. Point releases and security updates can change package revisions, so record the actual repository snapshot used for each build. The following official trixie package pages were read on 2026-09-28:

This session's **read-only** `/etc/os-release` reports `Debian GNU/Linux forky/sid`; `apt-cache policy` reports installed `qt6-base-dev` **6.10.2+dfsg-16**, `cmake` **4.3.4-1**, and `debhelper` **14.5** from testing. It reports `qtkeychain-qt6-dev` **not installed**, with testing candidate **0.17.0-1**. These are host observations, not trixie versions or proof that the package builds on stable. Developing against Qt 6.10 or debhelper 14 alone risks producing a package that cannot build or run on Qt 6.8/debhelper 13. Use a clean trixie amd64 build environment and a separate trixie XFCE/X11 runtime environment for acceptance. [Debian's `sbuild` guide](https://wiki.debian.org/sbuild) documents clean, ephemeral chroots; [Debian Policy](https://www.debian.org/doc/debian-policy/ch-source.html#main-building-script-debian-rules) requires noninteractive builds without network access in required targets.

The `debian/control` build dependencies should include `debhelper-compat (= 13)`, `cmake`, `qt6-base-dev`, and `qtkeychain-qt6-dev` if QtKeychain is chosen. Add only the development packages selected for spellcheck, archives, image formats, EPUB/DOCX/PDF, and other parity features; the editor/export work has not yet selected those implementations. The runtime `Depends` must include `${shlibs:Depends}` and `${misc:Depends}`; declare external programs and dynamically loaded components explicitly when dependency scanning cannot find them. In particular, depend on `xdg-utils` if `xdg-email` is the shipped mail path. The stable Qt XCB plugin lives in `libqt6gui6`, while the separately packaged [`qt6-wayland` 6.8.2-4](https://packages.debian.org/trixie/qt6-wayland) is a later Wayland validation item, not part of the current XFCE/X11 gate. [Debhelper shared-library dependency documentation](https://manpages.debian.org/trixie/debhelper/dh_shlibdeps.1.en.html), [Qt XCB plugin file list](https://packages.debian.org/trixie/amd64/libqt6gui6/filelist).

For the later package implementation, use `debian/source/format` as `3.0 (quilt)` for this non-Debian-specific upstream project, `debian/rules` with `dh`, and CMake install rules that stage executable, desktop entry, icons, and resources beneath `/usr`. The phrase “native `.deb`” here describes the native desktop build and Debian delivery; it does not mean Debian's special `3.0 (native)` source format. [Debian New Maintainers' Guide](https://www.debian.org/doc/manuals/maint-guide/first.en.html), [Debian Policy's `dh` recommendation](https://www.debian.org/doc/debian-policy/ch-source.html#main-building-script-debian-rules), [`dh_auto_configure`](https://manpages.debian.org/trixie/debhelper/dh_auto_configure.1.en.html), [`dh_auto_install`](https://manpages.debian.org/trixie/debhelper/dh_auto_install.1.en.html).

APT can manage a locally installed `.deb`, but it can discover **future versions automatically only through a configured package source**. An ongoing update channel therefore needs a trixie-targeted, signed APT repository with a `Signed-By` scoped key and published package versions. Until that repository exists, offer updated `.deb` files for explicit APT installation; do not claim `apt upgrade` will find them. Remove the current Electron self-updater and upstream `hughhowey/neo` release lookup from the native program's update path. Show package version and, if useful, a link to release notes without letting the app overwrite `/usr`. [APT sources](https://manpages.debian.org/trixie/apt/sources.list.5.en.html), [APT archive authentication](https://manpages.debian.org/trixie/apt/apt-secure.8.en.html), [third-party repository guidance](https://wiki.debian.org/DebianRepository/UseThirdParty), [current updater source](../../main.js), [current publish identity](../../package.json).

## Identity, paths, and library compatibility

The [current package metadata](../../package.json) still says `neo`, `NEO`, `com.hughhowey.neo`, and publishes under `hughhowey/neo`. The [main process](../../main.js) stores secrets below Electron `userData` and resolves the library as the Documents directory plus `NEO Library`. [Pocket](../../pocket/README.md) uses `/storage/emulated/0/Documents/NEO Library` and the same plain-file layout. The native program must use LEO for window titles, About text, the desktop entry, icon/app ID, private XDG directories, error-report destinations, and update/release identity. It must continue to find and save the **existing `NEO Library` directory** and preserve `library.json`, book JSON, chapter HTML, auxiliary files, domain markers, and unknown fields. It must not rename the shared directory or silently import it into an app-private directory. [Source inventory](https://github.com/soubarnak/leo/blob/da40475632f36e5f3cca92ffcd986fc6412c96e3/docs/research/void-native-parity.md), [library compatibility decision](https://github.com/soubarnak/leo/issues/4#issuecomment-5843571906).

Use `QStandardPaths::DocumentsLocation` to propose the Documents location, then recognize an existing library or let the writer select its established location; do not create a second empty library merely because the host's Documents directory is localized or redirected. The Debian [`xdg-user-dir` manual](https://manpages.debian.org/trixie/xdg-user-dirs/xdg-user-dir.1.en.html) describes configurable `DOCUMENTS`; [Qt 6.8 standard paths](https://doc.qt.io/qt-6.8/qstandardpaths.html) supplies `DocumentsLocation` and application-specific data/config/state/cache paths. Treat the following as **examples under default XDG settings**, not hard-coded strings: `~/.local/share/leo-writer` for native userData and local recovery snapshots, `~/.config/leo-writer` for settings, `~/.local/state/leo-writer` for logs/session state, and `~/.cache/leo-writer` for disposable caches. Honor absolute `XDG_*_HOME` overrides and create directories on demand. Recovery snapshots must not live in cache or in the synced library. The [XDG Base Directory specification](https://specifications.freedesktop.org/basedir/latest/) defines the defaults and state/data distinction; the [library decision](https://github.com/soubarnak/leo/issues/4#issuecomment-5843571906) requires separate local recovery history.

Set the visible Qt display name to `LEO` and set Qt's desktop file name to the chosen desktop ID without `.desktop`. Keep the configured application name/path suffix stable across upgrades. Do not assume Electron's encrypted `secrets.json` can be read by QtKeychain; ask the writer to re-enter credentials unless a separately proven migration exists. Leave legacy private data intact during package operations. [Qt application display/desktop names](https://doc.qt.io/qt-6.8/qguiapplication.html), [Qt standard paths](https://doc.qt.io/qt-6.8/qstandardpaths.html), [existing secret code](../../main.js).

## XFCE/X11 integration and degradation

**Launcher and files.** Install one validated FreeDesktop entry in `/usr/share/applications`, with `Name=LEO`, `Type=Application`, `Terminal=false`, a package-owned icon, `Categories=Office;WordProcessor;`, and an `Exec` that invokes the collision-free command. Debian Policy requires a transparent PNG/SVG icon of at least 22×22 and uses dpkg triggers to refresh menus; no legacy Debian menu entry is needed. [Debian Policy §9.6](https://www.debian.org/doc/debian-policy/ch-opersys.html#menus), [desktop entry specification](https://specifications.freedesktop.org/desktop-entry/latest-single/), [Office category](https://specifications.freedesktop.org/menu/latest/category-registry.html), [WordProcessor category](https://specifications.freedesktop.org/menu/latest/additional-category-registry.html). Only add `Exec=... %f` and `MimeType` entries after command-line file opening/import safely handles one file, including a second invocation. Advertise only formats the app can actually import (current source handles DOCX, TXT, Markdown); do not claim `inode/directory` for the `NEO Library` folder or turn LEO into the default handler for all text files. A desktop `MimeType` declares support; the user's `mimeapps.list` controls defaults. Installer scripts must not overwrite those user defaults. Register custom MIME XML only if a new unique format is introduced, which is not part of this identity rename. [Current import source](../../main.js), [desktop `Exec` field codes](https://specifications.freedesktop.org/desktop-entry/latest-single/), [MIME association rules](https://specifications.freedesktop.org/mime-apps/latest-single/), [shared MIME database specification](https://specifications.freedesktop.org/shared-mime-info/latest-single/).

**Notifications.** Use the session's `org.freedesktop.Notifications` interface for optional progress/sprint notifications. XFCE's `xfce4-notifyd` implements the FreeDesktop notification specification on trixie. Query capabilities rather than assuming actions or markup, and handle an absent session bus or server without aborting writing. Save failures, backup failures, and destructive-operation outcomes require durable in-app status or dialogs; a transient notification alone is insufficient. [Notification specification](https://specifications.freedesktop.org/notification/latest-single/), [Debian XFCE notification package](https://packages.debian.org/trixie/xfce4-notifyd).

**Secrets.** Use the trixie QtKeychain Qt6 package with a working Secret Service or KWallet provider for persistent optional API keys. QtKeychain's [upstream README](https://github.com/frankosterfeld/qtkeychain/) states it reports an error without a provider and writes unencrypted data only when `setInsecureFallback(true)` is explicitly requested. Never request that fallback. Do not put credentials in the library, LEO-owned XDG files, backup archives, lookup attributes, crash logs, or command-line arguments. The [Secret Service specification](https://specifications.freedesktop.org/secret-service/latest-single/) allows locked collections and says lookup attributes may be unencrypted. GNOME Keyring is available in trixie, but its installation does not prove a provider is running or unlocked in XFCE. If storage is absent, locked, or cancelled, keep ordinary writing available and disable persistent online features; an explicitly entered session-only key may remain in memory without being saved. [Debian QtKeychain runtime package](https://packages.debian.org/trixie/libqt6keychain1), [Debian GNOME Keyring package](https://packages.debian.org/trixie/gnome-keyring).

**Email snapshots.** The old app saves a timestamped PDF in `NEO Library/Exports`, then uses Gmail with manual attachment or macOS `osascript`; it has no Linux native attachment implementation. Preserve the PDF and SHA-256 provenance text before starting a mail handoff. For this unsandboxed Debian build, `xdg-email --attach <existing-pdf>` is the smallest documented desktop route; its [trixie manual](https://manpages.debian.org/trixie/xdg-utils/xdg-email.1.en.html) says it opens the preferred composer and may require the file to remain present after the command exits. Its exit status cannot prove the mail client actually attached the file or sent mail. The [trixie Email portal interface](https://github.com/flatpak/xdg-desktop-portal/blob/1.20.3/data/org.freedesktop.portal.Email.xml) also supports `attachment_fds`, but the [trixie GTK backend source](https://github.com/flatpak/xdg-desktop-portal-gtk/blob/1.15.3/src/email.c) forwards `attachment=file://...` through a `mailto:` URI to the selected client. That likewise proves handoff, not attachment acceptance. The implementation may choose either route after testing a concrete stable client. It must preserve the saved PDF, report handoff failure, distinguish portal request cancellation where observable, ask the writer to verify the attachment, and offer explicit manual attachment when automatic handoff is unavailable. `xdg-email` cannot report whether the writer later cancels or sends the compose window. Gmail browser compose remains a manual-attachment option. No path may claim an email was sent merely because compose opened. [Current snapshot source](../../main.js), [current fingerprint source](../../app.js), [portal request outcomes](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Request.html).

**Dialogs, theme, and absent components.** Qt Widgets uses the system XCB platform plugin for the initial XFCE/X11 target. The GTK Qt platform theme is available for native fonts/icons/dialog appearance, but must be validated on a real XFCE session; a missing optional theme should leave functional Qt dialogs. Mail client, notification server, and secret provider may each be absent. Their absence must have the feature-specific behavior above, without preventing launch or risking manuscript data. Wayland/niri is deferred; future validation needs the separate `qt6-wayland` plugin and session tests. [Qt Linux/X11 deployment](https://doc.qt.io/qt-6.8/linux-deployment.html), [Debian GTK platform theme](https://packages.debian.org/trixie/qt6-gtk-platformtheme), [Debian Wayland plugin](https://packages.debian.org/trixie/qt6-wayland).

## Evidence required from implementation

These are future acceptance gates. This research session installed no package and ran no application tests.

1. **Build and package ownership:** Build a source package and amd64 `.deb` in a clean trixie environment. Record the trixie archive snapshot, resolved build dependencies, CMake/Qt versions, package manifest, `Depends`, and `lintian` output. Inspect that Qt libraries and plugins come from Debian packages, no updater writes into `/usr`, and the `.deb` owns no manuscripts, recovery snapshots, settings, or secrets. Validate the desktop file with `desktop-file-validate` and check the file list for `/usr/bin/leo` or any other collision. [Debian `sbuild`](https://wiki.debian.org/sbuild), [`lintian`](https://manpages.debian.org/trixie/lintian/lintian.1.en.html), [`desktop-file-validate`](https://manpages.debian.org/trixie/desktop-file-utils/desktop-file-validate.1.en.html).
2. **Install, upgrade, remove:** In a disposable trixie XFCE/X11 image, install the `.deb` with APT and exercise launcher, icon, XCB startup, file-opening invocation, and runtime dependency completeness. Upgrade to a later package version, remove, reinstall, and purge; document which package-owned files disappear and prove the copied library, backups, exports, XDG user data, and keyring entry survive package operations. Do not make maintainer scripts traverse home directories. If an APT repository is offered, prove an upgrade is actually discovered from that signed source. [Debian Policy configuration behavior](https://www.debian.org/doc/debian-policy/ch-files.html#configuration-files), [APT sources](https://manpages.debian.org/trixie/apt/sources.list.5.en.html).
3. **Library and Pocket compatibility:** Use synthetic/copied multi-book libraries, including non-ASCII names, unknown metadata, document markers, covers, darlings, and exports. Show that native open/save preserves files and that both the old desktop app and Pocket reopen a native-saved copy. Show no accidental second `LEO Library`, no silent conversion, safe device handoff, and recoverable conflict/interrupted-save outcomes. A package upgrade must not become a data migration by surprise. [Library decision](https://github.com/soubarnak/leo/issues/4#issuecomment-5843571906), [source inventory](https://github.com/soubarnak/leo/blob/da40475632f36e5f3cca92ffcd986fc6412c96e3/docs/research/void-native-parity.md).
4. **Session services and secrets:** On trixie XFCE/X11, capture successful notification delivery and missing-server fallback. Prove a synthetic API key can be written, read after restart, removed, and never appears in library, XDG plaintext files, backup archives, or logs. Exercise locked store, cancelled unlock, missing provider, failed write, and credential re-entry from old Electron data. [Secret Service locking](https://specifications.freedesktop.org/secret-service/latest-single/), [QtKeychain behavior](https://github.com/frankosterfeld/qtkeychain/).
5. **Mail flow:** Create a synthetic PDF snapshot with a known fingerprint; inspect the saved PDF and draft subject/body. With one documented trixie mail client and default `mailto:` handler, verify the **actual attachment in the compose window** for ordinary and Unicode/space-containing paths. Repeat with no mail client or portal backend and show the saved PDF plus clear manual-attachment instructions. Keep the draft unsent during validation unless sending is separately authorized. A zero exit code or portal success alone does not pass. [trixie `xdg-email` manual](https://manpages.debian.org/trixie/xdg-utils/xdg-email.1.en.html), [portal backend source](https://github.com/flatpak/xdg-desktop-portal-gtk/blob/1.15.3/src/email.c).

Package metadata, desktop specifications, and source code establish feasibility and constraints, not an end-to-end Debian acceptance result. Exact mail-client attachment behavior, XFCE theme selection, secret-provider availability, package ownership after purge, and library round trips remain implementation evidence. The proposed command and app ID remain provisional because the LEO product name collides with an existing Debian command.
